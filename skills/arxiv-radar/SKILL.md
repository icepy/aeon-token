发现层的第一条通道。

## 为什么是 30 天，不是 7 天

**窗口是流量旋钮，但这条通道的旋钮被索引滞后卡死了。**

- 索引滞后实测 **5 天**（`窗口内最新收录` 连续 5 天没动）→ 7 天窗有效覆盖只剩 **2 天**
- 30d 首跑实测：26 条幸存，与 `seen` 重叠 **0**，`published` 全在 09-28→10-17
- 成本几乎为零：24 词 / 62 原始 / 97s

首跑会一次性推出沉积层（`NOTIFY_TOP=30` 不会截断），之后即稳态。

**但旋钮只在词表对得上时有效。** 实测：那 26 条在**旧 20 词表**下 7d / 30d / 90d **三档都看不见** —— 同一片存量上，10-25 的 90d 正式跑原始 90、幸存 0；两次跑唯一差异就是新加的 4 个 `cat:cs.RO` 词。**词表对不上时，拉多长窗口都是零。**

所以窗口的真实作用只有两件：① 抗索引滞后（5 天）；② **词表改动后的补历史** —— 加词 / 改 carrier 后跑一次 `days:60`，别只靠 30d 默认值。

**顺序不能反：词表决定你能看见什么，窗口决定你能不能补上错过的。**

## 各通道有自己的有效域

**本通道结构上就是 AI / 机器人传感器。** 实测：同一有效窗口内加密词 0 条、机器人词 26 条（真零 10 词里 6 个是链上/加密词）。

- 加密词留着当**低频探针**，别因 0 命中删
- **跨通道比较只在有效域内做** —— 别假设三条平行探针会同步点亮
- 单侧读数（一侧 0 / 一侧 26）每轮必须记

## 为什么用 arXiv

它是唯一"项目起源 + 有中心索引"的交叉点：论文先于主网、先于上市、先于叙事。PEARL 那篇 2026-06-03 的论文如果被扫到，提前量是 4 个月。

**但记住：arXiv 索引的是「机制」，不是「项目」。** 项目名（XMAQUINA）多半全期零命中；普通英文词（NOTE）会被英文用法污染。所以词表要写**持仓依赖的机制**，不是持仓的名字。

## 词表在哪

**全在 `skills/arxiv-radar/scan.py`。** `TERMS` / `CARRIER_BY_TERM` / `EXCL` 都在那个文件里，改词改那里，**不要在 SKILL.md 里再抄一份**。

## 铁律

- **预算是铁律：全程 ≤ 7 次工具调用。** 成本 = 调用数 × 每次重读上下文（~53k）。脚本自己的请求数不算在预算里。**别用 `python3 -c` 探产物结构** —— 先看有没有子命令。
- **通知正文归模型，不归脚本。** 脚本能算（列表），模型能写（中文 + 按簇分组）。脚本不会翻译英文标题，所以默认只写 `report.md` 的机械版当备用稿；模型覆写成中文后自己发。**忘了发不用重跑** —— `out.json` / `report.md` 还在，补发即可。
- **审计全文打在 stdout —— 它本来就短（~35 行），不需要 digest。** 全文同时落 `output/arxiv/audit.log`。`--full` 尚未实现，会被当未识别 token 忽略。
- **日志用 bash `>>` 追加，不 Read。**
- **产物文件名固定**（`out.json` / `audit.log` / `report.md`）。轮次号写进日志内容，不写进文件名。
- **只用 `ti:`。** arXiv 的 `abs:` 是松散匹配（`abs:"MEV"` 会命中兆电子伏特）。绕不开时用 `cat:` 约束整条查询。
- **写长短语，不写单词。** 单词必然撞别的学科（MEV / SNARK / liquidation 都是这么死的）。多词**必须带引号**：`ti:foo bar` 会被解析成 `ti:foo AND bar`，后面的词掉成全字段搜索。
- **零命中 ≠ 废词，也 ≠ 可删词。** 看 `raw_term`，不看 `per_term`。脚本自动对真零词补比本轮窗口更宽的档（30→60d；7→30/60d，更窄的档是蕴含的）。**三档全零连续两轮才谈动作 —— 而动作是先「降级为低频」，不是删。**
- **删词门槛要高：一个词的边际成本 = 1 次请求 ≈ 3s。** 加密侧在 arxiv 只有那几个词，删了就整条通道归零。
- **有词 ≠ 有召回。** 旧 4 个机器人词对同期机器人论文召回 **0/88**（90d），却安静躺在词表里；修法是换写法，不是加窗口。**每轮看 `raw_term`：长期 0 命中、而所属标签下有流量 → 写法错了。**
- **加词前必须量两个口径：`total_count` + 重叠度，并看前 3 条标题。** 用 `check:<词>`，别手搓。否则重演 `jepa` 654→35。
- **加词 / 改 carrier 后跑一次 `days:60` 补历史** —— 要量"能不能召回"需要比 30 天更宽的存量（旧词 0/88 那次就是 90d 量出来的）。
- **`egocentric` 单点脆弱。** 主命中 53.8% / 含它 69.2%，且 7d 与 30d **完全一致**（稳定词面特征，非窗口假象）。整条机器人通道压在一个词上 —— 该补 2–3 个同义写法（先量重叠度，只留带来新条目的）。
- **加新领域的词必须同时配 carrier 并登记 `CARRIER_BY_TERM`。** 一组链上 carrier 会把整个机器人簇误杀（实证：20 篇 `embodied AI` 论文一个链上 carrier 都不含）。
- **看到 0 命中，先看 `raw_term`、跨窗三档和「窗口内最新收录日期」。** 收录日期比今天早 **5 天以上**就是索引滞后，不是零命中。
- **单词集中度每轮必记。** 高但主题词在词表语义内 → 判真簇，不改词。
- **不做判断，不复述内容。** 只给名字 + 一句话 + 链接。

## Steps

### 1. 跑（一次 bash，就这一条）

```bash
python3 skills/arxiv-radar/scan.py "${var}"
```

脚本自己解析 var、拉取、过滤、写全部产物。审计全文打 stdout。**默认不发通知。**

加词前先量：

```bash
python3 skills/arxiv-radar/scan.py "check:world model"
```

### 2. 写通知（非 dry-run 且幸存 > 0）

一次 bash：把 `output/arxiv/report.md` **覆写成中文**，同一条命令里发出去。

```bash
cat > output/arxiv/report.md <<'EOF'
**arxiv-radar** · 窗口 30 天 · 幸存 26

**簇一 · 第一视角人类数据 / 人类示范（18）**
- `SocialCoAct` — 第一视角社交协同动作的 VLM 人形基准 · https://arxiv.org/abs/2610.24559
- `Ego2Contact` — 从第一视角人类视频预测接触 · https://arxiv.org/abs/2610.22932

**簇二 · 数据引擎 / 真机–仿真–真机（4）**
- `CoDA` — 数据引擎与动作策略共演化 · https://arxiv.org/abs/2610.22362
EOF
./notify -f output/arxiv/report.md
```

- **名字 + 一句话 + 链接**，按簇分组，**不做判断**、不复述内容
- 名字和链接**从审计里抄**，别手打
- 簇的划分是你要做的那一点判断（`probe` 式的同主题聚合），别省略

### 3. 写日志（bash 追加，不 Read）

往 `memory/logs/${today}.md` 追加一节 `### arxiv-radar`：口径 + 漏斗 + 四分类（**必须分开写**）+ 窗口内最新收录日期 + 单侧读数 + 单词集中度 + 你自己的判据级发现。零命中就只写一行。

### 4. 输出

- 通知已在上一步发出
- 只给名字 + 一句话 + 链接，按簇分组，不做判断
